## 2. 时间基准与 offset

1. **时间基准按目标游戏行为。** Phira：谱面时间 = 音乐时间 −（`META.offset` + `info.yml` offset），依据 TeamFlos/phira 源码（文档描述的符号相反，以源码为准，待黄金对照确认）。osu：按 .osu v14 语义。音频统一用固定版本的 ffmpeg 解码，记录编解码器。
2. **整体 offset 诊断（每张谱一个数）。** 用 10 ms log-mel（与 Pupu 前处理同配方）的正向谱通量包络，去掉 0.5 s 局部均值；在 ±200 ms 范围内以 1 ms 步长，求音符头时刻与包络的最佳平移 δ，同时记录置信度 conf 与 ±20 ms 吻合率（平移前后各一）。δ>0 表示音符偏早。
3. **系统性常数。** 对每个（来源，编解码器）组合，在 train 上取 δ 的中位数 c，作为解码延迟常数，记录在案；残差 r = δ − c。
4. **处理规则（只做整体平移，绝不逐音符吸附）：**
   - |r| ≤ 25 ms：原样使用（处于人际一致性噪声范围内）。
   - 25 ms < |r| ≤ 120 ms，且 conf ≥ 3，且平移后吻合率比平移前至少高 0.15：模型视图整体平移 r，记入出处；原生谱面与 sidecar 不改动。
   - 其余情况（|r| > 120 ms、conf < 3、搜索边界、平移后吻合率 < 0.3）：隔离，并记录原因。
   - 同一音频的多张谱：各自的 r 相差超过 25 ms 时，标记 `offset_disagreement`，供复查。
5. **与设计包 §6.1 的出入：** 设计包禁止"把人谱对齐到算法峰值"。本规则只修正一个全局常数，这是配错音频 offset 或设备延迟造成的作者错误，不是音乐取舍。逐音符的位置一律不动。val/test 用同一规则，保证评测标签与训练口径一致。
6. 抽样依据（40 张 Phira，修正时间基准后）：δ 中位数 0 ms，|δ| p50 11 ms、p90 63 ms；|δ|>20 ms 占 35%，>50 ms 占 16%；conf 最小 2.21。旧流程测出的"48% 超过 20 ms"中，有一部分来自 offset 只取一处的 bug。

## 3. 拍线 / BPM

- **谱面的拍线不当作音乐节拍的真值。** Phira 的 BPM 段可能是为演出效果（变速、停顿、视觉）或补拍设计的；osu 也有借 BPM 制造特效的情况。
- **不引入机器学习节拍检测作为模型输入。** 实测不够准（旧笔记：beat_this 的 F@20 ms 约 0.62）。
- 每张谱计算拍线可靠性诊断：音符头落在自身拍线 1/16 或 1/12 细分 ±3 ms 内的比例；BPM 段数量、最短段时长、相邻段 BPM 比值。满足以下任一条的谱标记 `timing_unreliable`：落格率 < 0.9；存在短于 1 拍的 BPM 段；相邻 BPM 比值不是简单比（1/2、2/3、3/4、4/3、3/2、2 之外）且段数 > 3。阈值随全量统计修订。
- P1 不使用拍位输入。之后若开放，只对未标记 `timing_unreliable` 的谱提供，并保留设计包规定的 50% dropout。任何情况下都不用拍线生成或修改标签。
- 原生 BPM、拍子有理数与 sidecar 照常完整保存，用于导出。

## 4. 质量隔离

沿用 P0 规则（重复音符、`bpmfactor ≠ 1`、`isFake ∉ {0,1}`、未知字段、非 v14 osu 等），另加 §2.4 的 offset 隔离。每张被隔离的谱都要记录原因代码；统计按代码汇总，用于决定规则是否过严。

## 5. 分组与划分

- 歌曲组 = 音频 SHA256 相同，或归一化标题相同（去掉括号限定词，如 remix、TV size、extended 等）。两条规则取并集，宁可过度合并，也不要泄漏。
- 80/10/10 按歌曲组划分，seed 20261022；划分在切窗之前完成。旧 `split_full128_final.json` 作废。

## 6. Modal 存储布局

Volume `beatfcn-data`：

| 路径 | 内容 |
|---|---|
| `raw/osu/audio/{sha256}.{ext}` | 原始音频，按内容哈希去重 |
| `raw/osu/charts/{beatmap_id}.osu` | 原始 .osu 字节 |
| `raw/phira/zips/{id}.zip` | 原始 Phira 包 |
| `mel10/{sha256}.npy` | float16 [T,128]，Pupu 归一化 10 ms log-mel；同时用于冻结编码、offset 诊断和细时间支路 |
| `canon/{source}/{chart_id}.json` | 规范事件与诊断 |
| `manifest/charts.jsonl`、`manifest/stats.json` | 每张谱一行：来源、音频哈希、歌曲组、划分、事件数、offset 诊断、拍线诊断、隔离原因 |
| `taps/...`、`pca/...` | 冻结编码输出（编码阶段写入） |

Volume `beatfcn-weights`：`teacher_encoder.safetensors`（在 Modal 内按 pinned revision 区间下载，SHA256 必须为 `6a97605541ba9d3680f6758e2ae19019736f03e5db14e8bbfbd71746b19304f4`）。

  - **系统常数 c 是来源约定，不是编解码器效应**：osu 的 mp3 与 vorbis 都是 c = +14 ms（n = 11,772 / 3,431）；Phira 的 mp3 为 −2、vorbis 为 −6。改为**默认在模型视图中扣除 c**（模型时间 = 原生时间 + c + 平移量 r），导出时按目标来源减回 c。理由：不扣除的话，两个来源之间存在 14 ms 的系统矛盾；扣除后 osu 的 |r| 中位 4 ms、p90 12 ms。
