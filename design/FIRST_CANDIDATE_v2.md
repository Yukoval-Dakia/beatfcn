# 第一候选 v2.1：全曲理解 + 更干净的时间头（2026-10-23，独立审查后修订）

状态：**设计收敛，审查意见已并入；实现前先做 §5 的零费用项。** 基于 `design/FIRST_CANDIDATE.md`（v1）、`reports/training_framework_review_2026-10-23.md`、`reports/transcript_arch_review_2026-10-23.md`、当天实测，以及 v2.0 的独立审查（12 条，本稿逐条采纳或标注）。v1 中未在此修改的部分继续有效；**v1 §2.1/§2.2/§2.7 的 H20 两秒均值摘要与"远程检索片段"废止**。

## 0. 结论

1. **不重写主干**：冻结多层全频段音频记忆 + 事件 Transformer 联合注意力 + 时间指针，保留（多层全频段 31.9% vs 27.2%）。
2. **新增一条可学习的"全曲理解流"**：块内编码器（自监督预训练后冻结、块 token 入缓存）→ 歌曲级 Transformer（每核心一次）→ 因果谱面块流；输出 S 作为**只读的 K/V 记忆**进入核心，取代 v1 的 G 行。结构、重复、强弱、风格一致性由注意力学出，不引入检索/复制等启发式。
3. **时间头 v2**：40 ms 格指针 + 从该格冻结 token 读出的格内毫秒偏移（支持区间 [0, 40)，不越界），onset 与长条尾部共用；"最近 K 个起音的相对间隔核"同时偏置格 logit 与偏移 logit。**10 ms mel 支路的去留由 §5.1 的相位探针决定。**
4. 训练与推理系统沿用当天已验证的实现：分桶 CUDA graph、有效组压缩、显卡常驻歌曲池（验证歌曲常驻）、增量解码。
5. 验收是**双重帕累托**：谱面质量不退（整曲评测各项）、端到端时间与总费用不增、至少一项改善。

## 1. 目标与验收

- 能力目标：更快、更高效、更强，更好的谱面制作协助（从零、补全、锚点、参考风格、控制量）。
- 质量指标（整曲连续生成，前文只含已知事件与模型自身输出），按模式分别报：
  - 完成率、独立合法性、onset F1（10/20/50 ms）、音符 F1（类型 + 时间 + mania 键道）、长条头尾联合 F1 与尾部误差；
  - **匹配后起音误差分布**（50 ms 内匹配，中位数 / p90；裁决时间头）；
  - **密度曲线相关性**：每 2 s 可编辑块的起音数曲线与真值的 Pearson r（≥10 块的歌），另报总量比；
  - **重复一致性**：段对由**音频**定（tap16 或 S 块 1 s 均值的 8 s 窗余弦，|Δt| ≥ 16 s，每歌 top 5%、≥3 对）；谱段相似度 = 两段起音（mania 加键道）Δ=0 对齐后 20 ms F1；报 P(模型复用 | 人复用, F1_true ≥ 0.5) 与 P(模型复用 | 人不复用)，不用比值；
  - IOI（起音间隔）对数直方图 KL、分段风格统计（hold 占比、和弦占比）方差；
  - **控制量响应**（`model/control_eval.py`）：以核心内单调率 ≥ 0.6 且在带率 ≥ 0.3 为"可用"（跨核心 Spearman 只作参考，它被核心间真值差异抬高）。
- 效率指标：训练每有效样本的时间与费用（含数据等待、启动、验证）；推理每首歌的生成时间。
- 泄漏规则：**标签**（当前及未来片段的音符和由其推导的量）不得进入任何输入或掩码；**音频随便看**。U 控制带是请求合同的输入（评测时不给真值带），不属标签。

## 3. 架构 v2.1

### 3.1 冻结音频记忆（不变）
PupuM2D Large，tap {9,16,24}，40 ms 格 × 8 频段 × 1024 维，全维度 int8 缓存（`v4_i8_L9-16-24`）。每核心 16 s 局部窗口（400 格）。

### 3.2 全曲理解流

| 层 | 输入 | 结构 | 输出 | 训练状态 |
|---|---|---|---|---|
| **块内编码器** | 每 **500 ms** 块：12–13 格 × 8 频段 × 3 tap 的冻结 token（LayerNorm + 频段嵌入 + 学习的 tap 混合） | 2 层 d=256 注意力（块内相对位置）+ 注意力池化（4 个可学习 query）→ 投影 d=512 | 每块 1 个音频块 token | **§5.2 自监督预训练后冻结，块 token 入缓存**（fp16，4 分钟歌 480 块 ≈ 0.5 MB） |
| **谱面块流** | 每块的谱面内容 = **全曲 O ∪ {隐藏事件且 onset < c0}**（含跨 c0 长条的尾部）；再加三个覆盖特征：块内 t<c0 的占比、editable 占比、empty 占比 | 事件嵌入 + 注意力池化（2 个 query），**并拼接块内占用网格的线性嵌入**（12–13 格 × 4 键道/类型，精确可逆） | 每块 1 个谱面块 token | 可训练 |
| **歌曲级 Transformer** | 音频块 token + 谱面块 token（相加）+ 池化后的 U 控制 + 全曲相对时间 RoPE（周期 1 s–2400 s） | 4 层 d=512、8 头、双向；长歌截断 2400 块（20 min） | 歌曲 token 序列 `S` | 可训练；**每核心一次**（谱面块流依赖 c0 与请求） |

- 不用"未知占位"：覆盖特征已区分"空块"与"尚未生成"，middle_holes / sparse_anchors 自然成立；O 在 c0 之后的块照常可见（与 K 行一致）。`summary_stats` 与 S20 缓存由谱面块流取代，删除。
- **S 在核心内的身份：只做 K/V 的记忆。** 与音频 K/V 同样逐层投影，K/Y 行可读，R/I/U 不读；S 自身不作为 query 行更新（否则 2400 行 × 8 层的 query 成本超过核心本身）。`encode_step` 的缓存加 S 的 K/V。
- 核心内 1D 时间 RoPE 周期上限从 120 s 扩到 2400 s（S 的 t = 块中心 − c0 可达 ±1200 s；v1 的 G 行已带混叠缺陷）。
- 自监督辅助目标（块内编码器预训练）：随机遮 15% 音频块，由一个临时的歌曲级 Transformer 回归被遮块的冻结特征均值；**报相对"邻块插值"基线的改进**，并加同曲块识别的 InfoNCE 项。只用音频，无标签。
- 代价（修正后）：块内编码器前向 ≈ 0.19 TFLOP/首，**不在训练图内**（预训练后冻结、缓存）；训练时可训练部分为歌曲级 Transformer + 谱面块流，每核心 ≈ 6.5 GFLOP 前向，≈ 0.6 TFLOP/步（核心侧 ≈ 13–15 TFLOP/步）。S 复用分桶轴 'S'，层级 {256, 512, 2400}。
- 参数增加约 15M。

### 3.3 核心事件模型
- 行集合：R / I / U / K / Y 为 query 行；**S 为 K/V 记忆**；可见性其余与 v1 相同（联合 softmax、GQA、K/Y 的音频时间窗）。
- **时间头 v2**：
  1. 指针在 200 个 40 ms 格 + END + COPY_TIME 上选格（格 key 来自局部音频 token）；COPY_TIME 在格级无冲突，copy_key 去 mel 后只用 token。
  2. 选定格后，用该格 8 频段 × 3 tap 的 token 与行 query 产生**格内偏移**的离散 logistic 混合分布，支持区间 [0, 40)（不越界：同一时刻只有一条路径，CE 目标唯一）；同格双起音靠偏移掩码 > 上一起音。
  3. **相对间隔核**：对最近 K=4 个起音，候选时刻与它们的间隔经可学习核（含整数倍/分数倍结构）得到偏置，**同时加到格 logit 与偏移 logit**；"最近起音"只取本行之前的组 `grp_t[:i]` 与 c0 之前的已知起音（O + 已生成，可在光环外，由 `build_core` 预算），**禁止 teacher-forced 的未来组**；带"无上下文"状态。不使用 BPM、不用节拍检测器（符合 DATA_RULES §3）。
  4. 长条尾部：块 → 格 → 同一个格内偏移头（共用参数）；长条块步改读 S 块 token。`gru_init_bg` 的 fine(t_new) 去 mel 后换为格 token。
- 内层组解码：保留 GRU（已有效组压缩）；"一次联合预测 80 类和弦形状"列为后续可选项。
- 取舍机制（I 行、选择场、L_cf）：结构保留；500 步配对无信号，**S1 配对改为 v1 vs v2（见 §5），取舍机制的配对实验推迟到 v2 之后**——这是待用户确认的决定。
- 暴露偏差：训练时只对 `is_generated` 行（K 行中来自前文的部分、谱面块流中的已生成事件）施加扰动——丢弃 10%、插入 5%（editable 内）、键道互换 3%、类型翻转 2%、时间抖动（幅度取模型当前实际误差，初值 ±20 ms）；在 worker 内做，并同步到谱面块流与间隔核输入；不动 O。S1 之后再考虑用近期 checkpoint 的 rollout 替换已生成上下文（DAgger）；scheduled sampling 与 CUDA graph 冲突，不选。

### 3.4 推理
- 增量解码（每组只算新的一行，已验证等价）；S 的 K/V 进缓存。
- 块 token 按歌缓存（冻结编码器）；歌曲级 Transformer 每核心一次；多首歌可批量。
- 内层采样向量化到设备（后续工程项）。

## 4. 训练系统（沿用）
分桶 CUDA graph（`TieredStep`，层级按微批 8 的实测形状分布：{G192,K256,S320,H320} 覆盖约 95%；超出最大层级即时执行；录制失败降级为即时执行）；有效组压缩；元数据 worker + 显卡常驻歌曲池（验证歌曲常驻、12 个加载线程）；CPU 预处理；缓存索引文件；占用率守卫；非录制反向固定侧流。

## 7. 风险与未决
- 歌曲流只通过各核心的局部损失拿梯度，长程信号弱 → 块内编码器由自监督预训练兜底；歌曲级 Transformer 若仍弱，再加遮块目标联合训练。
- 记忆越长暴露偏差越重 → §3.3 的扰动必须同时启用；整曲评测看完成率与误差积累。
- 取舍机制：结构弱点（参考音频频段被固定 query 池化；选择场是 8 个与音频无关标量的加权；配对少）；配对实验推迟（待用户确认）。若重启，按评审建议改成上下文内分类器（闭式岭回归）。
- S2 仍是旧数据路径：窗口去重按歌曲、冻结 1–20 层缓存第 20 层窗口状态，未实现。
- 40 ms 格对理解够用，对定位靠格内偏移头；两支路都受 10 ms hop 与 osu |r| 中位 4 ms 限制，1 ms 只是参数化。
- 显存：块内编码器不在图内；S 轴层级 {256, 512, 2400} 的 K/V 记忆按核心复制 B 份，最长歌时 2400 × 8 层 × 2（K/V）× d → 需在 #2 后实测。

## 7b. 实现记录（2026-10-24，代码 = 本节为准）
用户决定放弃对照、只训一个 v2.1 完整版（预算 ≤ $11）。为此实现上做了四处与 §3.2 不同的取舍：
- **块内编码器端到端训练**，遮块回归作为辅助损失（权重 0.1）在同一次训练里做，不单独预训练、不缓存块 token（省一次 $0.5–1 的全库读写和一条缓存路径）。遮块掩码由块时间与计数确定性地伪随机生成，保证即时/图/压缩三条路径逐步等价。
- 块内编码器读**后两个 tap、每隔一格**（80 ms）的 int8 单元格，整首歌常驻显卡，经自定义 autograd Function（`Int8MixProj`）投影，不保存浮点副本；静态输入缓冲从约 30 GB 降到约 10 GB。
- 谱面块 token = MLP(块内占用网格 10 格 × 4 × {起音, 长条活动} + 覆盖特征 + 类型计数)，不再有集合编码器（网格在 40 ms 上已无损）。
- 长条终点的 2 s 块步仍读 S20 摘要行（未改为 S 块 token）；mel 支路已移除，相位探针（§5.1）结果用于决定是否以额外输入形式加回偏移头。
其余按 §3.2–3.3 实现：S 作为 K/V 记忆、RoPE 周期 20 ms–2400 s、时间头 v2（格指针 + 共享偏移头 + 间隔核，不越界）、长条尾部共用偏移头、上下文扰动（worker 内，仅训练）。

## 8. v2.0 → v2.1 变更记录（独立审查 12 条）
采纳：1 成本修正（冻结 + 缓存块 token）；2 歌曲级 Transformer 每核心一次；3 S 作 K/V 记忆；4 跨 c0 块规则与覆盖特征；5 泄漏路径（间隔核前文规则、U 为合同输入、测试扩展）；6 RoPE 周期；7 时间头（不越界、核偏置偏移、探针协议）；8 占用网格嵌入 + 500 ms 块 + SSL 基线与 InfoNCE；9 扰动集合与 DAgger；10 评测定义；11 实验规模、臂与门槛、预算；12 废止条目与参数账。待用户确认：S1 配对改为 v1 vs v2.1、取舍机制配对推迟。
