# BeatFCN 实施规格包

本包是架构、数据和训练的实现合同，日期 2026-10-22。它没有模型权重、训练器或已完成的产品代码。

## 文件

- `BeatFCN_Architecture_Training_Data.md`：完整设计、两候选、研究命题、公式、训练课程、缓存、验收与实现顺序。
- `defaults.yaml`：固定初始配置；骨干路径/revision/hash 在实际下载并核验后写入 run manifest，不能伪造。
- `request.schema.json`：JSON Schema Draft 2020-12 的新增补全请求。
- `request.example.json`：虚构的 30 秒 mania 请求，含完成区、未来锚点、跨边界已有长条、待补区和明确留白。
- `response.example.json`：仅为接口示例，不是模型生成结果，不说明音乐质量或软控制达成。

## 两候选

A 是相对采音选择机制；B 使用相同输入与事件骨架，关闭选择场和其辅助/反事实损失。阶段 1 冻结、阶段 2 最后四层 LoRA 是训练安排，不增加候选。

## JSON Schema 之外必须实现的检查

1. 区间 start < end，完整覆盖 [0, audio_duration_us)，无重叠；ID 唯一。
2. 事件在音频范围内；非 hold 的 end=onset；hold 的 end>onset；模式和 location/type 一致。
3. 原生引用存在，导入时间/位置与固定版本渲染器一致，原事件及 sidecar 可保真合并。
4. 完成参考中的所有实际音符都已提供；sparse 参考不得产生未选中标签。参考外开始、但在参考内活动的长条也需通过 native chart 提供占用上下文。
5. observed 中的活动 hold 在生成开始时成为占用，未来所有 observed 进入精确约束索引。
6. 新事件的头和整个活动区间位于允许区域；原有人类事件保持；新 hold 不跨越 closed/empty 区或不兼容占用。
7. controls 的范围下界<=上界；unsupported 组合/不可满足的锁定内容返回具体原因。软目标不等于硬保证。
8. Phira 的 line_id/坐标域/场景变换有效；声明二指时有明确 profile，复杂移动仍需实际试玩。
9. 训练时 prefix/intent/全曲谱面摘要不读隐藏目标，endpoint 细节在预测 block 之后读取，真值数量和目标对照池不作为输入。
10. 模型视图先按可表示时间量化再建组，原 O 保持精确；组必须非空、时间严格递增；无法表示或无法细分的超限样本显式隔离/报告。
11. 严格反事实支持只改变 selected 位；属性全部同样遮蔽，并排除双方共享的 40 ms 选择场 cell。
12. 派生控制在留白等增强之后按 editable 区间并集重算；H20/H24/投影缓存分别按实际权重依赖失效。

## 实施入口

按主文档 P0→P5 推进。先做数据与编辑协议、32 样本可学习性，再做小规模同预算 A/B；通过后扩大到全量和 LoRA。模块名与脚本名为待实现接口，不能把配置文件当作已经可直接启动训练的程序。

本包给定的显存、延迟和盲评数字是验收目标；训练步数、采样比例和 loss 权重是固定起始值。没有进行 GPU 训练、性能测量、盲评或真实曲谱生成。
