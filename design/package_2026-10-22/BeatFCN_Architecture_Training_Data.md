# BeatFCN：协作制谱的架构、训练与数据实施规格

日期：2026-10-22  
状态：设计已收敛；配置为第一轮工程初值，尚未训练、跑 GPU 基准或证明质量。  
适用目标：5k–10k 张 Phira / osu!mania 谱面的迁移学习；从零写谱、任意区域补全、示例引导、难度与偏好控制。  
本规格从任务重新设计，不以 v24 或此前模型结构为前提。

## 0. 决策摘要

只保留两个候选，共用数据协议、音乐编码器、事件表示、约束执行器和产品接口。

| 候选 | 固定定义 | 用途 |
|---|---|---|
| A，主方案 | 时频音乐记忆 + 单个事件组 Transformer + 完成示例中的选中/未选中证据 + 相对采音选择训练 | 争取学会人的采音取舍，并向未写段落迁移 |
| B，唯一对照/回退 | 相同音乐、参考、权限、上下文和事件模型；关闭显式选择场与反事实损失 | 检验新机制是否值得保留；A 不胜出时可以交付 |

冻结阶段与 LoRA 阶段是同一候选的训练过程，不是另外两条架构路线。第一轮不再搜索其他音乐骨干、扩散/掩码生成或多个模型尺寸。

**核心研究命题：在相同音乐、相近负荷下，人类已经选择哪些声音、略过哪些声音，能否改变模型在另一段音乐中的采音选择？**

参考条件、风格 token、Q-Former 和自回归补全均有先例。本项目的待验证贡献是“完成区域的相对选择证据 + 严格的同曲支持交换任务 + 可编辑事件生成”这一具体机制。没有宣称全球首创，也没有把注意力图当作理解音乐的证据。[S3–S6]

## 1. 产品任务与权限合同

模型学习：

`p(new_events | audio, observed_events, paired_references, region_states, controls, scene)`

### 1.1 输入必须分开表达

| 输入 | 语义 |
|---|---|
| 音乐 | 完整录音；由音频哈希标识，允许同曲多谱复用 |
| 已有事件 O | 当前目标谱中的人类事件，默认全部不可修改；包括未来锚点 |
| 参考 R | 人指定或训练构造的音谱示例，覆盖为 complete 或 sparse；用于示范写法，不自动加入目标谱；只有 complete 提供未选中证据 |
| editable | 允许新增；没有音符处仍是未知；区内可有不可修改的零散锚点 |
| complete | 该段已经完成，其已有音符和空处均确定，不允许新增 |
| empty | 明确要求留白，不允许新增音符头或长条占用 |
| controls | 模式、负荷目标、类型偏好、示例强度；缺省与数值 0 不同 |
| scene | Phira 判定线与运动环境，或 mania 的键数/键道环境 |

时间区间统一为左闭右开。完整请求的区域划分覆盖全曲且不重叠；事件头在区间右端归下一段。长条占用采用半开区间，结束时刻的再按键另由玩法的 release gap 规则决定。

从零生成使用 `O=[]`、`R=[]`、全曲 editable；意图 token 使用学习到的默认状态。部分谱并不自动成为“完成参考”：只有覆盖状态明确的片段才提供未选中证据。

### 1.2 输出是新增 patch

返回 `additions`、每个请求区域的 `completed/partial/infeasible/resource_exhausted` 状态、需要人工审阅的原因、复现用模型版本与随机种子。原事件及其 native sidecar 由程序保持；不让网络重写原谱。

只保证本次可控的对象：新增事件格式、权限与形式化约束。遇到原有锁定内容与新约束冲突，返回冲突，不能修改人谱来伪造成功。空输出是可能的合法选择，但评估必须同时报告空结果率与可用完成率，不能靠拒绝所有请求获得“零违规”。

### 1.3 第一版 Phira 范围

生成 tap / hold / flick / drag 的时间、判定线、上下侧、位置和长条结束；已有判定线动画、速度和视觉对象作为场景条件保留。从零使用一个可选的静态判定线模板。完整演出动画的自动创作不纳入这次模型质量承诺。

## 2. 确定的网络结构

### 2.1 音乐编码器

- PupuM2D Large，24 层、1024 维、16 头；保留原始 2D patch 与预处理。[S1, S2]
- 参数预算采用用户已核对的约 403M 编码器权重口径；论文/模型卡的 307M 标签不可替代实际张量统计。初始化时锁定权重哈希、代码版本，并统计实际加载的 encoder 子集。
- 原生输入 24 kHz mono；128 mel；hop 240 samples；4×16 时频 patch。每秒 25 个时间位置、每位置 8 个频率 token，即 200 patch token/s。[S1]
- 10.24 s 原生窗口，步长 5.12 s，仅保存中心 5.12 s 的精细输出。首尾做显式 padding 并保存有效 mask。训练与部署使用相同铺窗方式；需验证接缝，不能声称天然无接缝。
- 精细证据 M 来自第 24 层；全曲摘要 G 从冻结的第 20 层提取。二者分别 LayerNorm，加入层来源/频率/时间标记后使用投影。
- 精细频率聚合器：1024→512，4 个学习查询在同一时刻的 8 个频率位置上做注意力汇聚，得到每 40 ms 四个 512 维 token。查询不跨时间；这四个槽不宣称是四种乐器。
- 全曲摘要先在 H20 原始特征上按 2 s 作确定性时间平均，保留 8 个频率位置，再在线投影/聚合。这样 LoRA 改变 21–24 层时，全曲摘要源没有陈旧问题。

选 Pupu 的理由是该方案需要时频证据，尤其要学习选择不同音乐成分；其 MIR 结果只支持采用它作为音乐表征起点，不等于已经证明人类采音理解。[S1]

### 2.2 一个事件 Transformer

| 项目 | 固定初值 |
|---|---|
| 层数 / 宽度 / 头数 | 8 / 512 / 8 |
| 每层 | pre-norm self-attention + music cross-attention + SwiGLU |
| SwiGLU 中间维 | 1536 |
| dropout | 0.1 |
| 意图状态 | 8 个学习 token，属于同一 Transformer 的条件前缀 |
| 同时组内解码 | 单层 GRU，hidden/input 256 |
| 默认生成核心 | 8 s；精细音频读取左右各 4 s，共 16 s |
| 全曲摘要 | 每 2 s 四个音频 token，附一个已知谱面摘要 token |
| 远程细节 | 最相关的 2 个 4 s 片段；读取音乐与可用人类事件 |
| 条件前缀上限 | 1536 token；全曲摘要最多 600 token |
| 当前核心生成上限 | 256 个 onset group，512 个新增事件；超过则细分核心，不能丢标签 |

粗略参数账：8 层主干线性矩阵为 `8 × (8d² + 3df) = 35,651,584`；加投影、字段头、GRU、归一化和嵌入，事件侧预计约 38–42M。LoRA 约 0.655M。总模型约 4.4 亿，可训练约 4 千万；实现后报告逐模块精确值。

这里不强求把可训练参数压到几百万。模型要学习变长结构、局部/全局关系和协作策略，事件侧需要实际容量。

### 2.3 前缀的可见性与防泄漏

前缀分为参考证据 token R、意图 token I、已知工作区 K、全曲摘要 G、控制 U。R 包括显式音谱参考，也允许把请求原始 O 的局部锚点转成 positive-only 音谱证据，coverage=unknown；本轮生成事件不得升级成人类意图证据。所有生成事件 Y 均位于后缀。

| Query | 允许读的条件 | 允许读生成目标吗 |
|---|---|---|
| R | R 中的配对音乐、事件/未选择标记、参考覆盖状态 | 否 |
| I | R 与 I；无参考时读默认状态 | 否 |
| K / G / U | 已知前缀；不得把完整隐藏目标做成全曲谱面摘要 | 否 |
| Y_i | 全部已知前缀与 Y_<i；音频记忆可双向读 | 只读过去生成组 |

参考与意图行的音频 cross-attention 只读取参考音乐；生成行读取目标的局部、全局及取回音乐。I 不受 teacher-forced 目标事件影响。参考编码与工作区编码使用同一套 Transformer 权重，按该 mask 计算和缓存，不增设独立意图主干。

附近已知事件，包括待补区右侧未来锚点，逐事件或无损同时组可见。远处事件提供全曲摘要和检索细节；全曲精确事件索引一直供约束器查询。不能把“远处有摘要”说成“整曲所有事件始终无损进入注意力”。

## 3. 新机制：完成示例中的相对采音选择

### 3.1 配对参考

每个参考包含两类 token：

1. 选中证据：完成片段中的音符，配上它附近的时频音乐证据及音符属性。
2. 未选中证据：完成片段中没有被写成音符的时刻，配上相同来源的时频证据和 `unselected` 标记。

未选中时刻一半从 log-mel spectral flux 的显著局部峰附近采样，一半从其他非音符时间采样；排除音符头附近 ±30 ms 及语义不明确的活动长条区。峰值仅用于采样训练对照，不负责最终放置音符，也不能自动标记“这是鼓/旋律”。

参考默认取 1–2 个完整 4 s 段，累计至多 16 s；正例至多 128 个、未选中至多 128 个。超密参考先缩短完整区间，再构造例子，不能把删掉的正例误标成未选中。所有未选中例子都必须有完成覆盖证明；未知草稿只贡献已有正例。

### 3.2 目标音乐上的软选择场

8 个意图 token 得到 Z。一个小读出让目标 M 的每个时频 token 查询 Z，再将频率维汇聚为每 40 ms 的选择分数 s(t)。按缓存中的实际帧时间映射取对应 cell 的分数，初版不插值。读出只读目标音乐和 Z，不读目标事件隐状态。

主时间头使用：

`logits_time(t) = logits_AR(t) + lambda × 2 × tanh(s(t)/2)`

`lambda ∈ [0,1]`，初值 0.5。作用是温和地改变采音优先级；任何合法时刻仍可生成。数量由自回归停止决定，后续类型/位置/长条头仍读取完整音乐。40 ms 的软场不决定最终时间分辨率。

Z 同时作为事件 Transformer 的可读前缀，用于类型、排布和长条关系；不把八个维度人工命名成“旋律/鼓/情绪”。若以后开放这些语义旋钮，必须补相应监督。

### 3.3 关键训练任务：相同音频池、等数量，只交换人的选择

从同一录音、同模式的两张真实完整谱 A/B 取互不重叠的支持区 S 与目标区 T。先校正 offset，将 ±30 ms 内的近同刻头对齐，排除仅时间抖动造成的伪差异。

- S 中取 A 独有的 K 个时刻和 B 独有的 K 个时刻，K 初值 8，允许 4–16。
- 两份支持使用完全相同的音频、候选时间池、长度、正负数量和显式控制。
- 支持 A 将 A 独有时刻标选中、B 独有时刻标未选中；支持 B 反过来。
- T 中找到相同意义的 A 独有与 B 独有事件。目标候选只用于 loss，不作为输入。
- 要求 A 支持下 s(T_A)>s(T_B)，换成 B 支持后反转。

CF 使用独立的严格对照视图：两份支持的 type/location/hold 属性统一设为同一种缺失标记，候选顺序、音乐、时间、padding 和控制完全相同，只交换 selected 位；同时隔离普通 R 与 O 派生证据，不能让其他前缀泄露两张谱的身份。普通事件生成样本仍保留完整属性。构造器对两份 CF 输入做逐字段相等断言，不能复用普通全属性 Z 后宣称完成了严格反事实对照。

完成 ±30 ms 对齐后，还须按实际 40 ms 选择场 cell 去重，并排除 S/T 两侧共享 cell 的差异；否则同一分数会被要求同时大于和小于自身。按唯一 cell 计算均值。同格的精细时间差只交给事件损失，不用于 L_cf。

损失用按候选数归一的均值，margin m=0.5：

`L_cf = 0.5 × [softplus(m - mean(s_A(T_A)) + mean(s_A(T_B))) + softplus(m - mean(s_B(T_B)) + mean(s_B(T_A)))]`

普通 onset BCE 只作为稳定辅助；上述任务才提供“同一音乐在不同人类取舍下应改变选择”的直接学习信号。

仅采用真实非嵌套差异。高难谱几乎包含低难谱所有事件时，不凭空造反向意图。不同谱师、不同歌曲或 batch 中其他参考不能一律作为负例。

### 3.4 数据不足时的明确处理

数据审计输出合格音频组数、独立 A/B 配对数、可构造的非重叠 S→T 任务数。若训练集中少于 50 个合格歌曲组或 300 个独立配对任务，A 的普通监督仍可训练，但不启动大额反事实训练，也不声称识别了取舍。

补数计划：约 100 首短音乐，每首选两个 8 s 段，分别写两种明确的采音思路，尽量匹配密度；保留选音理由与多选/不确定标注。按歌曲重新分 train/val/test；训练集不足通过新增歌曲补齐，不能挪用测试曲。可先做 20 首确认标注协议与实际差异，再扩充。

若无法获得有效配对，B 是明确的产品候选。A 不能用随机翻标记来伪造“人类双意图数据”。

## 4. 事件表示与完整解码

### 4.1 统一事件对象

事件保存 `event_id, onset_us, end_us, type, location, native_ref`。数据层另外保留精确原生 beat 有理数、offset、格式版本和 sidecar。模型输入可用浮点，保存层不可损坏原始对象。

- mania_4k：type 为 tap/hold，location 为 lane 0–3。
- Phira：type 为 tap/hold/flick/drag，location 为 line_id、side、native_x。
- 同时音符全部保留。组内排序只是序列化规则：mania 按 lane；Phira 按 line/side/x/type。
- 原始 IR 按精确规范时间保留事件关系；单独建立模型视图：隐藏新增事件先按自由时间 1 ms 规则量化，再按模型时间建组；与已知锚点精确同刻的目标优先用 COPY_TIME。原 O/native sidecar 不量化。量化造成同键冲突或非正 hold 的样本隔离记录，不静默改坏原谱；teacher forcing、group feedback、endpoint loss 统一用该模型视图。不把整段压成固定 1/16 拍格，也不将多个类型合并成一枚音符。

### 4.2 外层按 onset group 推进

每步先选 `END_GAP` 或一个新组时间。时间使用相对当前核心起点的 10 ms coarse bin，加 0–9 ms residual。另提供指向本核心已知锚点时间的 COPY_TIME 指针，允许新增音符与精确人类时刻形成和弦。

新的自由时刻按 1 ms 表示；这是数值分辨率，绝不是已经达到 1 ms 对齐精度。已有事件不经过该量化。

主 Transformer 每个同时组运行一次。组内 GRU 初始化于外层状态、组时间、当前占用，依次预测：

`CONTINUE/END_GROUP → type → location → hold_end (仅 hold)`

每个字段读取之前已经选择的字段；每枚音符读取本组此前的音符。组大小未知，由 END_GROUP 决定；不提供真值数量或 N 个 MASK 槽位。4K 同组最多四个不重复 lane，Phira 按场景与触点约束决定。

首枚音符之前禁止 END_GROUP，保证每个生成组非空。组结束后，自由时间和 COPY_TIME 都必须严格晚于上一生成组；第一组可以位于 gap 起点。空区域只用 END_GAP 表达，不能用空组循环或同刻拆组绕过约束。

给下一个外层步的 group embedding 只由已完成组的时间/属性计算，例如共享 note MLP 后 sum/max pooling；不直接使用依赖外层状态的 GRU 最终 hidden。这样训练时外层 teacher forcing 可并行。

### 4.3 长条结束位置

长条整体是一个对象。其结束按三步预测：

1. 指向全曲 2 s endpoint block；这套 block 网格固定，和长曲上下文摘要的自适应桶宽分开。
2. 读取该 block 周围精细音乐缓存，预测 block 内 10 ms coarse bin。
3. 预测 1 ms residual。

先预测 block，才可读取对应细节。训练的 teacher forcing 仅在该条件步骤之后使用真实 block，避免把真实结束位置提前漏给 pointer。endpoint block 描述可以由冻结 H20 按 2 s 汇聚，均可缓存；实际细节使用当前模型的 H24。

结束可越过多个 8 s 生成窗，但新长条的整个占用必须位于允许写入的连通区，且不穿过冲突的已知事件或明确留白。主干不预测单独的游离 hold-end 事件。

### 4.4 多空洞与跨窗状态

按时间处理相交于本核心的 editable gaps；每个 gap 可立即结束。仅当前核心拥有 onset，防止窗口重叠造成重复。已经生成的事件进入后续上下文；跨入下一核心的长条以 ACTIVE_HOLD(start,end,location,source_id) 初始化占用，不能重新生成其头部。

每个 gap 的训练用同一权限状态机。复杂段超过 token 上限时切为 4 s、2 s 等更小核心，保留完整同时组和 carry state；禁止静默截掉标签。若固定 halo 的锁定事件或一个不可拆同时组仍超上限，返回 resource_exhausted 并记录原因，不能无限细分或丢事件。

## 5. 上下文与计算边界

### 5.1 局部、全曲与远程细节

- 当前核心精细音乐共 16 s；完整保留局部未来已知事件。
- 全曲默认每 2 s 四个音频摘要，加一个已知谱面摘要，进入条件前缀，使其能相互注意并被生成序列读取。
- 最多 600 个全曲摘要 token；更长录音增大摘要桶宽，保留绝对秒和拍位坐标。
- 固定 H20 音频摘要上做同曲片段相似检索，取 top-2 非局部、尽量不重叠的 4 s 片段；显式人类参考永远优先保留。
- 取回片段的谱面部分只能来自当前请求已有的 O/R 或本轮已生成事件，不能从训练真谱查询隐藏答案。

这是对 DSA“先找相关远程信息，再取细节”的任务化应用。第一版不引入完整 lightning indexer 或其专用训练；原 DSA 主注意力与索引器的成本并不相同，不能把它当免费长上下文。[S7]

### 5.2 缓存键与失效

缓存按真实依赖分级：H20 原始缓存包含 audio hash、预处理/铺窗/padding、前 20 层权重、层位置与精度，不包含上层 LoRA；H24 再加入后四层及 LoRA 版本；投影音乐/全曲摘要再加入相应 LayerNorm、频率聚合、投影与来源嵌入的版本。事件侧缓存另含事件模型和 observed/reference/region/control/scene hash。这样既避免过期复用，也不会让每次 LoRA 更新无故清空冻结 H20。

推理时权重固定，一遍音频前向同时取得 H20 全曲证据与 H24 精细证据；可以保存投影后的音乐记忆。修改人谱和偏好只重算工作区/事件侧；改变参考重算参考意图状态。不能把任意编辑假设成可直接复用全部 AR KV 的追加操作。

训练时投影器仍在学习：只能缓存其输入，不能冻结旧投影结果后继续声称端到端训练该投影器。

## 6. 数据处理流水线

### 6.1 导入与保真

1. 按格式版本解析 osu/mania、RPE/PEC。PEC 先通过已验证的语义转换器规范化，不以文本存在就当解析成功。
2. 以音频播放时间为统一基准。保存原 beat 有理数、BPM 段、offset 与 native sidecar；按渲染器行为核验各格式 offset 符号与单位。
3. mania 区分真实 BPM timing point 与 inherited speed point；不能将负 beatLength 当成负 BPM。RPE 处理多 BPM、line bpmfactor、父子线和影响判定位置的运动语义。[S8, S9]
4. playable notes 与 fake/decorative notes 分开；后者保留在 sidecar/场景，不直接作为可玩输出目标。
5. 质量检查：时长正值、边界、事件重复、键道范围、完整 hold、音频缺失、异常 offset；疑似问题进入隔离清单并记录原因，不静默修成另一张谱。
6. 用少量固定 golden cases 对照原生 renderer 的判定时间和位置，再开始大规模标签生成。

自动 onset/beat 工具只能提供弱辅助；不得把人谱对齐到算法峰值，以免抹掉人工切分、拖拍或长音取舍。

### 6.2 拍位的可用性

物理时间始终可用。协作请求有可靠 timing map 时加入拍位、局部 BPM、拍内相位；只有音频时允许拍位缺失。训练至少 50% 样本隐藏精确 timing map，避免从零任务依赖完整目标谱的 BPM 信息。若日后加入音频拍点估计，需以同一估计器训练和评测，单独报告置信度；不能把 oracle BPM 结果混称纯音频结果。

### 6.3 去重、划分与采样

- 在切窗前建立 audio group 与 composition group：相同录音的不同编码、静音偏移、不同难度/谱师归同组；同曲速度变体及明显近重复另行聚合，存可审查证据。
- 80/10/10 按歌曲组划 train/validation/sealed test，seed 固定；训练参考、控制归一化、量化标定与检索训练统计只从 train 构造。验证/测试可以读取该请求明确公开的完成支持区 R；它属于合法条件，隐藏目标 T 仍不可进入任何条件或缓存。
- 分别报告谱面数、录音数、歌曲数、有效小时数与模式分布。
- 采样顺序：模式（概率正比该模式歌曲数平方根）→歌曲→该曲谱面→请求。限制某首多难度歌曲对训练的支配。
- 不输入歌曲 ID、谱师 ID、文件名或等级标题作为捷径；来源信息留在 provenance 中。

## 7. 训练样本如何构造

| 基础请求 | 比例 |
|---|---:|
| 从零 | 20% |
| 已完成前缀后的续写 | 15% |
| 中间洞 / 多个洞，左右可有完工区 | 25% |
| editable 内只有零散不可修改锚点 | 20% |
| 完成参考 S → 不重叠目标 T | 20% |

另交叉叠加约 20% 显式留白、20% 边界长条案例；不是另加到 100% 之外的互斥任务。留白一半从自然空处取，一半模拟用户主动禁止某区：同步删除该区的隐藏新增目标并保留 provenance，不能同时拿原有音符作为必须生成的真值。若会影响锁定对象则重采样该掩码。

掩码按时间或已有拍位采样，不按真实隐藏音符数摆放。稀疏锚点不是完成区。跨越 editable/complete 边界的真值 hold 必须整枚作为 O，或在不侵入保护区的前提下扩展 editable；不能让它成为一个按权限本来就不可生成的目标，更不能裁短。模拟明确留白时，整枚移除与留白占用相交的隐藏新增事件，不能只删除头或尾。结构化缺失（只保留长条、重复动机或经过真实标注的一个声部）加入锚点任务，但与真实编辑会话分开统计。

参考 S 与目标 T 必须互不重叠，且先做歌曲组划分。目标的音符、局部真实数量、目标对照候选、完整真谱摘要不得进入参考/条件缓存。

反事实批次在支持数据足够时每四个 optimizer step 增加一次；单独统计额外前向与时间。B 的训练按实际 GPU 时间/处理量匹配，而不以相同步数假装算力相同。

## 8. 控制条件与监督边界

初始控制包括模式内难度标签（可缺省）、平均密度范围、峰值负荷范围、hold 头比例、hold 占用率、同押比例、mania jack/交替倾向、Phira flick/drag 倾向和区域强度曲线。

- 官方等级仅在各自玩法中校准；4K 是布局，二指是执行约束，不能当成同一个 mode bit。
- 可解释统计从训练谱导出；使用分档/范围条件，避免把目标 8 s 的精确 NPS 编码成真实数量。
- 默认统计范围固定为请求的 editable 区间并集：NPS 计该范围内 O 与保留目标的全部音符头；hold 占用率是活动 hold 与该并集相交的时间并集占比，包含区外开始的已有 hold。量化、模拟留白等增强完成后重算派生控制，再分档；无法重算的字段设为缺省。训练与推理采用同一定义，不混用全曲密度和局部密度。
- 全控制向量 20% dropout；保留时每字段再 20% dropout。缺省标志单独编码。
- 不能任意随机改变 hold_ratio 后，仍把相反的原谱当唯一真值。优先使用真实多难度/多谱对，或保持目标统计位于条件范围内。
- 评估时用用户指定或完成参考推导的控制；使用隐藏目标统计的实验必须标为 oracle。
- “偏旋律/偏鼓/更悲伤”等命名旋钮仅在获得标签后开放。第一版可用用户的完成音谱示例表达这种偏好。若要训练命名声部控制，准备约 300–600 个短片段的多选/不确定标注。

音乐情绪与某一种谱面动作不存在一一对应。验证应看段落强弱、休止、动机和表达是否合适，不能因为骨干做过情绪分类就声称制谱已懂情绪。

## 9. 损失函数与优化

主目标：

`L = L_event + 0.2 L_select + 0.1 L_cf`

系数是固定起始值，各项先按有效对象归一。B 使用相同 L_event，保留相同参考信息、权限及模型容量预算，关闭两项显式选择机制。

### 9.1 L_event

- outer action / 时间粗格 / 细格 / COPY_TIME 指针的条件交叉熵；END_GAP 单独归一，防止海量空段支配梯度。
- inner CONTINUE/END_GROUP、type、lane/line/side 的条件交叉熵。
- Phira x 用 5 分量有界 logistic mixture 的负对数似然，按场景的允许坐标域归一。采样顺序和合法坐标域必须与训练一致。
- hold endpoint block/coarse/fine 的条件交叉熵。
- 每字段以“出现该字段的真实事件数”归一，避免稀少 hold/type 被 tap 数量淹没。若使用类型权重，以 train 的逆平方根频率估计并限幅 [1,4]。

只对新增隐藏事件与必要停止符求生成损失；不是让模型重复预测 O 后再删除。已有事件虽然无生成损失，仍作为条件传递梯度到事件模型。

### 9.2 L_select / L_cf

L_select 是目标 40 ms 时间格的 selected-head 辅助 BCE，正负采样平衡；不是声部标签。它不负责最终数量，也不硬屏蔽主生成器。L_cf 仅在合格真实配对上启用。

不默认加入 RL、任意跨歌负样本 InfoNCE 或多个相似的风格一致性损失。先验证主生成与相对取舍机制能被使用。

## 10. 两阶段训练与预算门槛

### 10.1 S0：协议和可学习性

- 32 个短片段，覆盖两模式、密集和弦、长条、未来锚点、明示留白、多 BPM 和 Phira 动线。
- 检查原生导入/导出不损坏人谱；在小集过拟合，核对所有字段梯度与前缀不可见目标。
- 只证明管线成立，不作泛化或产品质量结论。

### 10.2 S1：冻结音乐，训练协作事件模型

- 先做 300–500 首独立歌曲 pilot，最多 3000 optimizer steps；每 500 step 验证，连续四次无改善且参考未被使用则暂停扩大。
- 主训练使用全部合格 5k–10k 谱；推荐按约三次 chart-hours 覆盖确定步数，封顶 22000；不是重复累加 pilot 的独立预算承诺。
- BF16（硬件支持时）；AdamW；新增模块 lr=2e-4，betas=(0.9,0.95)，weight_decay=0.01；warmup 500；cosine 最低 lr=2e-5；clip=1；激活 checkpoint。
- microbatch 初值 2、accumulation 16，等效 32 个 8 s 请求；发生显存压力时改为 microbatch=1、accumulation=32，保持有效 batch。按实际 token/音频秒记录，不能只写 batch size。
- 前 1000 step 将选择损失系数从 0 线性升至目标；反事实任务在基础时间/类型学习稳定后启用。
- 首次预计算使用 BF16 H24 中心特征与 H20 原始摘要。int8 原始缓存仅在小样本重建和端到端对照通过后启用；不得仅凭“能读取 int8”认定质量无损。

### 10.3 S2：固定的短程联合适配

- 只在第 21–24 层加入 rank=8、alpha=16、dropout=0.05 的 LoRA；目标是 fused qkv、attention output、SwiGLU fc1/fc2；基础权重冻结，前 20 层 no_grad。
- 在 d=1024、fc1 输出 8192、fc2 输入 4096 的实现下，LoRA 共 655360 参数；若实际代码命名/形状不同必须按加载结果重新统计，不盲目匹配字符串。
- 新增模块 lr=5e-5，LoRA lr=5e-6；最多 3000 step，每 500 验证。
- 不向音乐编码器注入人类条件，保持音频缓存边界。制谱损失通过局部/参考/hold 终点的音乐读出回传到适配参数。
- H20 全曲摘要源不变，但其在线投影仍学习；H24 细节一律由当前 LoRA 重算，不能读 S1 的旧最终缓存。
- 完整 H20 缓存必须保存原生 2048 patch 排列、RoPE 坐标、padding 与 block20 原始输出，不能用池化/最终 LayerNorm/截中心结果替代。
- 以歌曲分桶采样，每个训练 step 对用到的原生窗口去重，增加 H20 重用。全曲随机小 LRU 不保证省去前 20 层计算。
- 保留 S1 checkpoint。S2 只有在留出歌曲的协作、长条和音乐质量无明显退化且至少一个目标有实质改进时采用，否则交付 S1。它是训练选择，不再开放其他 LoRA 网格。

### 10.4 开销记录

每次训练记录：optimizer steps、生成核心秒、独立 encoder 原生窗口数、参考/远程/hold endpoint 额外窗口数、H20 命中率、tokens、GPU 时间、I/O、峰值显存。先测 100–200 个稳定 step 和 20 首歌曲的冷编码，再估全量。

费用估算为：音频预计算时间 + 训练步时 + 验证/渲染时间，乘实际 GPU 报价，再加存储/流量。没有设备实测时，不给出“100 元训练完成”或“4GB 必定运行”的承诺。

## 11. 约束生成与合法合并

### 11.1 mania

每键维护全曲 interval index；每次采样屏蔽同组重复 lane、同键 hold 冲突、越过未来锁定占用的 end、不可写区域、禁用类型与越界。有效 end 区间从当前键未来占用得到，在 block/coarse/fine 三层分别应用掩码。

### 11.2 Phira 与二指

位置要经过当前判定线/父线/旋转/移动的变换求接触坐标，不能直接比较不同线的 native_x。保留少量左右手分配状态，结合活动 hold、flick/drag、时间间隔和手部移动约束进行可行性筛选。

二指检查相对一个明确的、用人工可玩谱校准的运动 profile；简单的“同时最多两枚 note”不足以保证二指。复杂场景可保守拒绝或标为待试玩，不能把形式化检查通过等同人体手感已验证。

### 11.3 有限回退与最终检查

候选先受约束再采样；无法继续时回退本轮最近最多两个生成组，最多尝试四次；不动人类事件。仍无法补齐则返回 partial/infeasible，并保留合法 patch 与具体缺口。

最终独立检查：所有原对象字段与 sidecar 保持、完成/空白区无新增占用、事件与边界合法、hold 完整、无重复 ownership、引用场景存在。输出还需导入目标游戏/渲染器检查。

## 12. 资源账与服务目标

以下是形状推算，单位 MB 为十进制，不是实际峰值显存。

| 对象 | 3 分钟一曲 |
|---|---:|
| H24 原始中心特征：25×8×1024×180，BF16 | 73.728 MB |
| 同形状 int8，不含 scale | 36.864 MB |
| 4 个频率槽、512 维，BF16 | 18.432 MB |
| H20 完整重叠原生窗口，约 36 窗×4 MiB | 约 144 MiB |

若 5k–10k 张谱恰好对应同样多独立的三分钟录音，原始 int8 中心缓存约 184–369 GB；BF16 是两倍。同曲多谱必须去重。H20 完整窗口库比中心缓存更大，按阶段清理/分片，不能默认全量同时常驻。

2760 个音乐 token、8 层、512 维的 BF16 cross K/V 约 45.2 MB；参考预填充、全曲谱面摘要、活动 hold 和 self K/V 另计。这个例子只说明缓存张量量级，不等于实际总内存。403M BF16 音乐权重约 0.81 GB，激活与框架 workspace 另外计算。

目标：在选定的 4GB 设备上，模型进程显存峰值不超过 3.5 GiB，留系统余量；热缓存 8 s、至多 128 新增事件补全 p50≤2 s、p95≤5 s。超过事件规模另列密度曲线。所有数字是产品验收目标，不是已测结果。

分别测：冷载入、整曲音乐编码、全曲生成、只改控制、修改锚点、修改参考。默认一次请求生成一个候选；用户请求多个方案才批量采样，避免把多候选重排成本隐藏在“单次时延”里。

## 13. 如何判定 A 是否构成有效进展

### 13.1 数据与协议硬门槛

锁定事件改动=0；完成区/明确留白新增占用=0；同键冲突与悬空 hold=0；跨窗重复头=0；训练/测试歌曲泄漏=0。合法完成率目标≥95%，同时报告空结果和 partial 比例。

### 13.2 核心能力测试

1. 同一目标音乐、相同控制、相同生成预算，切换两种真实完成示例；检查模型能否相应改变采音。
2. 同曲等数量、相同音频候选池，只交换 support 的 selected/unselected；目标是支持选择迁移，不是歌曲识别。
3. 在少量人工确认的音色/声部区别集上，移除支持音频但保留时间/拍位，或打乱音频配对；若性能不降，不能声称声部理解。
4. 中间洞与未来人类锚点衔接；跨窗长条；长条结束的音乐依据与手型。
5. 控制按 3–5 档扫描，检查响应方向、误差与副作用。首轮要求至少 80% 支持范围内歌曲方向正确；分别报告 hold 头比例和占用率。
6. 真正的人类半成品会话 60–100 个，记录采纳、删改事件数、达到可用状态的编辑时间。

### 13.3 公平对照

B 必须获得相同参考、选中/未选中输入、全曲摘要与远程检索；配对 A/B 的支持→目标样本也提供给 B 求常规事件损失，不能让 A 独享配对监督数据。两候选的参数预算和实际 GPU 时间匹配。A 的 CF 增加了前向次数，要计入预算。先同预算 pilot；仅当差异不清楚时补 seed，不做无边界网格搜索。

诊断消融包括：正例支持、打乱选择标记、移除 L_cf、关闭选择场、去掉支持音频。它们用于定位增益，不作为额外产品架构候选。

### 13.4 晋级规则

在固定验证请求上预先锁阈值，再开 sealed test。A 在“延续参考思路”的盲评中，目标为非平局比较胜率≥60%，按歌曲聚类 bootstrap 的 95% 区间下界>50%；同时编辑时间目标下降≥15%，可玩性/hold 指标无预先定义的实质退化。样本不足则报告不确定，不宣告突破。

一般事件 F1 按 10/20/50 ms 分别报告，hold 头尾、列位/位置、类型分别算。参考不唯一，不能用一个 F1 排出所有写法的优劣。用人为时间偏移、循环重复、长条冲突、乐句重排等破坏测试检查指标是否敏感；ChartGenEval 的思想可以借鉴，其现成 Taiko 标定不能直接复制到这两个玩法。[S10]

若 A 的收益不能超过同信息 B，关闭新机制交付 B；保留反例继续研究，不用复杂度或名字替代证据。

| 工作包 | 产物 | 进入下一包的条件 |
|---|---|---|
| P0 数据/编辑合同 | canonical events、native sidecar、JSON schema、split manifest、golden cases | 时间/场景保真；O/R/complete/editable/empty 无混淆 |
| P1 基础生成 | 音乐读取、prefix mask、group Transformer、GRU、hold pointer、约束器 | 32 样本可学习；任意空洞与长条往返成立 |
| P2 人类选择机制 | signed reference、8 intent tokens、软场、合格配对 builder | 目标不可见；真实支持交换能产生可测差异 |
| P3 同预算 pilot | A/B 学习曲线、成本、控制与音乐评测 | 核心指标有效；确定是否采用 A |
| P4 全量与短程适配 | S1/S2 checkpoint、分模式结果、最终配置 | 相比 pilot 增益成立；无音乐/协作退化 |
| P5 编辑器闭环 | 局部 patch 预览/接受/撤销、热缓存、复现日志 | 目标设备性能、真实协作与导出试玩通过 |

待实现模块接口（文件名只是本规格的接口约定，不代表已存在可运行代码）：

- `data/canonicalize.py`：原谱/音频→规范事件与 sidecar。
- `data/group_split.py`：去重分组、固定划分。
- `data/requests.py`：从真谱构造 O/R/权限/控制/隐藏目标。
- `data/intent_pairs.py`：合法同曲 A/B、非重叠支持/目标与反事实标签。
- `audio/memory.py`：原生铺窗、H20/H24、缓存元数据与检索。
- `model/prefix.py`：严格前缀可见性，意图预填充。
- `model/group_decoder.py`：outer Transformer、inner GRU、时间/位置/hold 条件头。
- `model/selection.py`：软场与相对选择 loss。
- `runtime/constraints.py`：全曲占用/权限索引与有限回退。
- `runtime/complete.py`：窗口 ownership、多空洞、跨窗状态、patch 输出。
- `train.py`：S0/S1/S2、精确参数和计算量日志。
- `evaluate.py`：协议、音乐、协作、控制、速度与盲评导出。

实现中所有 checkpoint 绑定数据 split、请求配方、预处理、骨干/LoRA、事件 schema 和场景解析器版本。旧版本文件可以提供输入样例，不能悄悄成为新架构的约束。

## 15. 来源及其支持范围

- [S1] PupuM2D, Frequency-Aware Self-Supervised Music Representation Learning: https://arxiv.org/html/2606.25713v3 。支持原生结构/预处理和 MIR 证据；不证明 BeatFCN 协作能力。
- [S2] 官方实现与权重：https://github.com/sizigi/PupuM2D ，https://huggingface.co/spellbrush/PupuM2D 。实现前锁定实际 revision/hash；不按网页标签代替张量统计。
- [S3] Anticipatory Music Transformer: https://arxiv.org/abs/2306.08620 。支持固定部分事件的条件补全范式；不是 Phira 实验。
- [S4] FIGARO: https://arxiv.org/html/2201.10936v4 。专家/学习式描述与可控符号音乐先例。
- [S5] MusicGen-Style: https://arxiv.org/html/2407.12563v1 。示例音频条件与瓶颈先例。
- [S6] Learning Music Style for Piano Arrangement Through Cross-Modal Bootstrapping: https://arxiv.org/html/2608.03050v1 。跨模态风格和 Q-Former 先例。
- [S7] DeepSeek-V3.2: https://arxiv.org/html/2512.02556v1 。选择性注意力思路；不提供当前模型的速度保证。
- [S8] osu! .osu format: https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format) 。timing point、键道与 hold 格式语义。
- [S9] Phira chart standard: https://teamflos.github.io/phira-docs/en/chart-standard/index.html ；目标播放器源码 https://github.com/TeamFlos/phira 。最终以固定版本解析/渲染一致性为准。
- [S10] ChartGenEval: https://arxiv.org/abs/2607.12857 ，https://github.com/JacobLinCool/ChartGenEval 。多维指标及破坏验证方法。
- [S11] Transfer Learning for Rhythm Game Chart Generation from Music Transcription and Across Games: https://arxiv.org/html/2610.14955v1 。支持迁移学习的相关性，也提示跨玩法收益需单独检验；其独立 5 s 生成及指标不等于本方案的协作、位置和长条能力。

所有模型尺寸、采样比例、loss 系数、训练步数和验收阈值，除明确引用的预训练结构外，均为本次制定的工程初值与研究协议。下一步可按 P0→P5 实现；本文件不是已训练模型或实验结果。
