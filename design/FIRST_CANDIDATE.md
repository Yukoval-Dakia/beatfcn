# BeatFCN 第一候选：解耦事件模型 + 冻结多层全频段音频记忆

日期：2026-10-22。状态：架构决议与实现合同；尚未训练，下文资源数字除标"实测"外均为形状推算。

输入材料：
- 设计包 `design/package_2026-10-22/BeatFCN_Architecture_Training_Data.md`（下称"设计包"，含 `defaults.yaml`、请求/响应合同）。
- handoff 分支实验 `experiments/shared_kda_s0a/`（共享 Pupu24 + KDA4，下称"handoff"），含本会话的冻结音频记忆修订与 MPS 实测。
- 两份外部评审意见："主动倾听 + 多层共生 MoT"提案（下称"第三方案"）与"选第二份文档"评审（下称"评审"）。

## 0. 结论

**第一候选 = 设计包的解耦架构（候选 A/B 体系、数据合同、事件解码、选择场、反事实损失、约束器、P0→P5 全部继承），只替换 §2.1–2.2 的"音乐如何进入事件模型"接口：**

1. 事件主干独立（8 层、512 维、自有 QKV/FFN），不再让谱面 token 穿过冻结的音频权重。
2. 事件主干每层用**同一个 softmax**联合注意 `[音频 K/V ; 谱面前缀/已生成 K/V]`；音频侧读冻结 Pupu 的**多层（默认 H8/H16/H24）、全部 8 个频段**，由每层可学习的层混合 + GQA（2 个 KV 头）投影得到，不做 4 槽静态聚合。
3. 音频与谱面共用一套绝对时间 RoPE（秒），音频另加频段/层来源嵌入。
4. S2 阶段在设计包原有的 21–24 层 LoRA 之外，可选加入意图 Z 的零初始化 AdaLN 调制，作为**预注册消融**，不是默认路径。
5. Pareto 优化（§2.7）：按时间开窗的音频注意力、按 bin 读音频的时间指针头、10 ms 细时间音频支路、选时后为组内 GRU 回读 t_new 处音频。推算下各项效率指标均不劣于设计包，并补上设计包缺少的 40 ms 以下音频证据和"新时刻音频"通路。

handoff 的共享 Pupu24+KDA4 不作为第一候选，降为参考实验保留。本会话做的缓存修复使它可训练、可在 MPS 上跑通原生窗口，但没有消除它的核心建模问题，效率也仍不如解耦架构（见 §1）。

## 1. 三份方案的说法逐条核实

### 1.4 评审的三条实施建议

1. 先用候选 B 打通 P0/P1，不被反事实配对数据卡住：**采纳**，与设计包"P1 基础生成 → P2 选择机制"的顺序一致，这里明确写出。
2. 外层每步加"距右侧最近锁定事件/editable 右界"的时间差特征：**采纳**（§2.4），只由 O 与区域状态派生，不读隐藏目标。
3. 推理期静态 KV 缓冲：**采纳**到 P5；其"8 s 补全 200–400 ms"是未测数字，不作承诺。

## 2. 第一候选的确定结构

除本节列出的替换项外，一律按设计包和 `defaults.yaml` 执行。

### 2.1 音频侧（冻结、可缓存）

- PupuM2D Large 冻结，原生 10.24 s 窗、5.12 s 步长、保留中心 5.12 s，预处理与设计包 §2.1 相同（复用 `beatfcn_s0/pupu.py` 严格 294 张量加载和 `preprocess.py` 官方 mel 配方）。
- **读取层（taps）默认 {8, 16, 24}**，保留每个 40 ms 的全部 8 个频段 × 1024 维原始输出（不过最终 LayerNorm）。另按设计包保留 H20 的 2 s 时间均值，用于全曲摘要、检索和长条端点块描述。
- S0b 一次性层探针：冻结特征上，对训练集歌曲的 onset 与 hold 头做逐层线性探针，只允许据此把低层 tap 从 8 改到 4–12 中最优的一层；结果写入 run manifest。这是一次性的定参，不是网格搜索。
- 选 {8,16,24} 的理由：低/中层各一层承担瞬态与音高，24 层承接 S2 的 LoRA。8 和 16 都低于 21，S2 的 LoRA 只会使 tap24 失效。

### 2.2 事件主干：独立权重 + 联合注意力

| 项目 | 定值 |
|---|---|
| 层数 / 宽度 / 头 | 8 / 512 / 8 × 64，pre-RMSNorm，SwiGLU 1536，dropout 0.1（同设计包） |
| 每层注意力 | 一个 softmax：query 为谱面行；key/value = [音频记忆 ; 前缀 R/I/K/G/U ; 已生成组]，按设计包 §2.3 的块前缀 + 因果掩码 |
| 音频 K/V | 第 ℓ 层：`m_ℓ = Σ_j softmax(w_ℓ)_j · LN_j(H_tap_j)`，再经该层自有投影得到 2 个 KV 头 × 64（GQA，8 个 query 头每 4 个共享 1 个 KV 头）。层混合权重、LN、投影都可训练 |
| 时间坐标 | 音频 token、前缀事件与生成组共用 1D 绝对时间 RoPE（单位秒，相对生成核心起点）；音频另加频段嵌入与 tap 来源嵌入。生成行用其上一完成组的时间，BOS 用 gap 起点 |
| 音频范围 | 与设计包相同：局部精细 16 s；全曲摘要 ≤600 token（H20 2 s 均值）；检索 top-2 × 4 s 片段（同样走多层全频段记忆）。这一项替代设计包的 4 槽频率聚合器与独立 cross-attention |
| 组内 GRU、COPY_TIME、10 ms + 1 ms 时间、长条块指针、Phira 5 分量 logistic 混合、约束器 | 全部按设计包 §4、§11 |

联合注意力与"self + cross 两次注意力"表达能力相近。选它的原因有两个：一次注意力更省；音频证据和谱面上下文在同一个 softmax 里竞争权重。它的收益没有被证明，不作为卖点。

### 2.3 意图与选择场

- 8 个意图 token 及其可见性（I 只读 R/I）同设计包 §2.3、§3。
- 参考 R 的选中/未选中证据 token 读取参考音频时，同样走 §2.2 的多层全频段记忆（只读参考音乐）。
- 选择场 s(t)：目标音频每个 40 ms × 8 频段的层混合记忆 token 查询 Z，再在频段维聚合。频段在**意图已知之后**才聚合，这正是对设计包"4 槽静态坍缩"的修正。读出不读目标事件隐状态，公式与 λ 同设计包 §3.2。

### 2.4 右侧锁定锚点距离特征

每个外层步与每个组内 GRU 步追加：到本 gap 右界、到右侧最近锁定事件头的时间差（对数刻度分档 + 截断），以及该锁定事件的位置嵌入（mania 键道 / Phira 线与侧）。只由 O 与区域状态计算，属于合法条件，并进入泄漏测试。

### 2.5 S2：LoRA + 可选主动倾听消融

- 默认 S2 同设计包 §10.3：21–24 层 LoRA r=8，H20 原生窗口缓存不失效。
- 预注册消融 "S2+Z"：在 21–24 层每个块的两处 pre-norm 后加零初始化 AdaLN，`(1+γ(Z))·LN(x)+β(Z)`；γ、β 由 Z 池化后经线性层得到，权重初始化为 0，因此起点与默认 S2 逐位一致。Z 只来自 R，严格反事实视图照常适用。代价：tap24 依赖参考，不能跨参考复用；切换参考需重算局部窗口的 21–24 层（MPS 推算约 0.2 s/窗口）。采用条件与 S2 相同：留出歌曲上参考延续盲评或选择迁移指标有实质改进，且其他指标无退化。

### 2.6 缓存与失效

| 缓存 | 键 | 训练期可跨步复用 | 体积（推算） |
|---|---|---|---|
| tap8/tap16 原始中心输出 | 音频哈希、预处理、铺窗、padding、前 16 层权重、精度 | 是（S1/S2 均不变） | 每 tap 73.7 MB/曲 BF16（int8 减半，须先通过端到端等价检查） |
| tap24 原始中心输出 | 上述 + 17–24 层权重 + LoRA/AdaLN 版本 | S1 是；S2 每步重算 | 73.7 MB/曲 BF16 |
| H20 2 s 均值 | 同设计包 | 是 | 很小 |
| S2 用 H20 原生窗口（含 RoPE/padding） | 同设计包 §10.3 | 是 | 约 144 MiB/曲 |
| 推理：各层音频 K/V（GQA） | tap 键 + 事件模型版本 | — | 16 s 局部窗约 13 MB；整曲约 147 MB |
| 推理：前缀 K/V、组状态 | 设计包 §5.2 事件侧键 | — | — |

训练期可训练投影的输出不可缓存，只缓存冻结的 tap 输出（与设计包 §5.2 原则一致）。

**存储方案（按本机约 136 GB 可用空间制定）。** 5 首样本谱音频平均 159 s；Phira 元数据按标题分组约 7,691 组。每首每个 tap 的原始输出 BF16 约 65 MB。

| 方案 | 每首 | 3,000 首 | 7,700 首 |
|---|---|---|---|
| 3 tap 全维度 BF16 | 196 MB | 588 GB | 1.5 TB |
| 3 tap 全维度 int8 | 98 MB | 294 GB | 755 GB |
| 设计包原版 H24-only int8 | 33 MB | 98 GB | 251 GB |
| 3 tap PCA-128 int8 | 12 MB | 37 GB | 94 GB |

1. Pilot（300–500 首）缓存 3 tap 全维度 int8，约 30–50 GB；在其上完成 §3 的预注册对照，同时对 PCA-128 int8 做端到端等价检查（与设计包"int8 须先通过端到端检查"同一规则）。
2. 全量缓存 3 tap 的 PCA-128 int8。PCA 只用 train 歌曲的冻结特征拟合（每个 tap 一个，8 个频段共享），拟合后固定，属于冻结预处理、可缓存；可训练的层混合与 GQA 投影接在其后，输入维度相应改为 128。PCA 版本与方差保留率写入 run manifest 和缓存键。若检查不通过，改用 PCA-256（全量约 75–190 GB）或缩减歌曲数，不改模型结构。
3. 不采用全程在线重算：每个请求约 10 个原生窗口、约 20 TFLOP，24 GB 级 GPU 上仅编码约 8 s/步，22k 步约 49 h。
4. S2 所需的 H20 原生窗口（约 144 MiB/首）全量同样存不下：S2 只在子集上按歌曲分桶、有界 LRU 在线重算（即设计包的 `bounded_lru_and_song_bucketing`）。

### 2.7 Pareto 优化（效率与效果同时改进）

在 §2.1–2.6 基础上确定加入以下五项。前四项修正设计包与第三方案都没有处理的问题，第五项是存储/带宽。

1. **按时间开窗的音频注意力。** 带时间坐标的 query 只读本行时间附近的局部精细音频：生成行（嵌入组 i−1，时间 t）读 [t−1 s, t+3 s)，BOS 以 gap 起点为 t；已知事件行读 [t−2 s, t+2 s)；参考证据行在参考音频上读 [t−2 s, t+2 s)。I、U 不读局部音频。全曲摘要与检索片段不开窗。长距离信息仍走全曲摘要、检索片段和下述时间指针。局部 key 从 3200 降到约 800，同时提供局部性偏置。
2. **时间指针头（替代 800 类线性时间头）。** 外层候选集合 = {END_GAP} ∪ 本 gap 内每个 10 ms 自由 bin ∪ COPY_TIME 锚点，在同一个 softmax 中打分。bin b 的分数 = `MLP_q(h_i) · MLP_a(audio(b) ⊕ fine(b) ⊕ relpos(b − t_prev))`，再加 §2.3 的选择场偏置；锚点用其时间与位置嵌入打分；END_GAP 是一个学习的空选项。每个 bin 直接用自己的音频打分，不必把"8 s 内哪里有音"压进隐状态。代价约为每步 800 次点积。设计包的"先选动作，再选粗格/指针"改为一次联合选择；严格递增、首组限制和权限掩码作用于同一候选集。1 ms 残差同样以所选 bin 的 fine(b) 为条件。
3. **细时间音频支路。** 从同一段 24 kHz 波形计算冻结、无参的 10 ms 帧 log-mel（128 维，复用 Pupu 前处理的 hop 240）与谱通量，再由一个小型可训练 1D 卷积编码，作为 fine(b) 进入时间指针与残差头。它补上 40 ms token 之下没有任何音频证据的缺口。只缓存无参输入，int8 约 2 MB/首。
4. **选时后的音频回读。** 组内 GRU 初始化时，用一次小交叉注意力读取 [t_new−120 ms, t_new+120 ms) 内的多层全频段 token（约 6 cell × 8 频段）和 fine(t_new)。之后的 type、键位/线、长条判断都以新时刻的音频为依据。这也让"哪个频段对应哪个键道/判定线"有了直接通路。
5. **GQA + PCA-int8 缓存**，见 §2.2、§2.6。

形状推算（每请求；生成+已知行约 768 个 query 读局部音频；8 层；尚未实测）：

| 维度 | 设计包原版 | §2.1–2.6 | 加 §2.7 后 |
|---|---|---|---|
| 训练前向 | 约 138 GFLOP | 约 160 GFLOP | 约 130 GFLOP |
| 训练读取音频缓存 | 约 9.8 MB（H24 BF16） | 约 1.8 MB | 约 2.4 MB（含细时间支路） |
| 每首缓存 | 33–74 MB | 12 MB | 14 MB |
| 解码每步读音频 K/V | 约 39 MB | 约 20 MB | 约 10 MB |
| 40 ms 以下的音频证据 | 无 | 无 | 有 |
| 新组 type/位置能读 t_new 处音频 | 否 | 否 | 是 |

效果一栏是结构性推断，不是实测。§3 的预注册诊断增加一项：§2.7 第 1–4 项整体关闭 vs 开启，在 P1 pilot 上按 10/20/50 ms F1、type/位置准确率与事件 NLL 比较；开启后若无改进，按项定位，只保留不降效果的项。

### 2.8 参数账（推算，实现后按实际张量重报）

- 每层：谱面 QKVO 4×512² = 1,048,576；音频 K/V 投影 2×1024×128 = 262,144；SwiGLU 3×512×1536 = 2,359,296；归一化约 1k。8 层合计约 29.4M（设计包同口径 35.7M，因合并 cross-attention 并用 GQA 而减少）。
- 加嵌入、字段头、GRU、长条指针、Phira 混合、意图、选择读出、全局投影，事件侧约 33–36M 可训练；音频骨干 403,141,632 冻结；S2 LoRA 655,360（形状须按加载结果核验）。
